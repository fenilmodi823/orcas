# Phase 4 M1.3 — Tier 0 Point Renderer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render the full catalogue (up to 46,250 objects) as GPU points in one draw call, positions driven live from M1.2's `FrameState`, over a correctly-scaled Earth — the "screenshot" milestone, first time the project has visible 3D satellites.

**Architecture:** A small pure core (`points-attributes.ts`, `points-shading.ts`) packs per-object static attributes and implements the apparent-size/brightness law as testable arithmetic, exactly mirroring what the vertex shader will do — the project's established pattern (M1.3-Explained.md §6.2) for making GPU-bound logic verifiable without a GPU. `points-geometry.ts` builds a `THREE.BufferGeometry` whose `position` attribute wraps M1.2's existing `FrameState.positions` buffer **by reference** (no copy), so per-frame updates are a single `needsUpdate = true` flag flip. `TierZeroPoints.tsx` is the R3F component: one `<points>`, one `ShaderMaterial`, uniforms recomputed cheaply per frame from the live camera. A new `/points` debug route (mirroring `/propagation` and `/keyframes`) mounts it against a locally-scoped, correctly-scaled Earth and reports draw-call count, frame time, and a 10-object cross-check table against direct SGP4 — reusing `PropagationDebug.tsx`'s already-proven "direct vs. derived" pattern.

**Tech Stack:** TypeScript strict, `@react-three/fiber` + `three` (already pinned, no new dependency), Vitest for the pure core, GLSL via `THREE.ShaderMaterial`. Builds directly on M1.0's `catalog-types`/`catalog-snapshot`, M1.1's `@orcas/physics` propagation, and M1.2's `frame-state.ts`/`use-simulation-loop.ts`.

**Spec:** `ORCAS Vault/03 - Engineering/Phase-4-Engineering-Brief.md` §B.1–B.3 (why GPU points beat meshes/`InstancedMesh`, the Tier 0 attribute table, the exact vertex-shader responsibilities) and §I "M1.3 — Tier 0 point renderer" (milestone goal, testing, DoD). Explainer walkthrough: `ORCAS Vault/03 - Engineering/M1.3-Explained.md` §2–§6. This plan implements that milestone; it does not restate the whole brief, so executors should have both open.

## Global Constraints

- TypeScript `strict: true`, no `any` (Rules.md §1/§3). Named exports. Files `kebab-case.ts(x)`, components `PascalCase`, hooks `use-thing.ts`. Files stay under 250 lines.
- Every function whose inputs/outputs carry units documents them in its docstring (Rules.md "Units and frames"). Positions here are km, J2000 frame — same convention `frame-state.ts` already uses.
- **No React state updated per frame.** All hot-path writes (position buffer flag, uniform values) go through refs / direct GL calls inside `useFrame`, never `setState`. This is the one rule this entire milestone exists to exercise correctly.
- **No new npm dependency expected.** `three`, `@react-three/fiber`, `@react-three/drei` are already approved and version-pinned — do not touch those pins. If a task turns out to need something new, stop and ask rather than adding it.
- Commits: Conventional Commits, one commit per task, imperative summary under 72 chars, no full stop.
- **Folder location: `frontend/src/renderer/points/`.** The brief's literal M1.3 paths (`renderer/points`, `renderer/device`, `apps/web/src/scene`) assume the §H pnpm-monorepo restructure, which M1.0/M1.1/M1.2 all deliberately did not adopt — everything so far lives under `frontend/src/`. M1.3 follows the same precedent. Decided and recorded in `ORCAS Vault/00 - Meta/Open-Questions.md` (Decided table, 2026-08-26).
- **No Playwright.** Two of the milestone's five required tests (visual regression at three camera poses, draw-call==1 assertion) genuinely need a real GPU and browser. Rather than adding a new end-to-end dependency (which needs ask-first justification per Rules.md §1/§6, and visual-regression suites are known to produce false failures across GPU drivers), these are verified by hand via the new `/points` debug route in a real browser — the same manual-live-verification pattern that already caught real bugs on M1.1's `/propagation` and M1.2's `/keyframes` that no unit test could. Task 7 below is that live check. Decided and recorded in Open-Questions.md, 2026-08-26.
- **Debug route is `/points`, not `/simulation`.** `/simulation` is reserved for M1.9's final integration route, same reasoning M1.2 used for `/keyframes`.
- **This milestone does not touch the real `/` route (`App.tsx`'s `Simulation()`), `packages/orcas-scene/src/Earth.tsx`, or `packages/orcas-scene/src/Satellites.tsx`'s existing usage.** Consistent with M1.0/M1.1/M1.2's own precedent (none of their debug routes touched the real route either). Two concrete reasons this matters more here than before: (1) `Earth.tsx` is a **shared** package (`packages/orcas-scene`, eventually consumed by the portfolio's demo island per CLAUDE.md — changing its radius from the current placeholder `1` scene unit to a real `6371` km is a real, consequential change to shared code, not a debug-route concern); (2) the real `Simulation()`'s camera (`position: [0, 0, 4]`) is tuned to that same placeholder scale — changing one without the other breaks the currently-working shipped scene for zero benefit this milestone. The `/points` route therefore renders its **own** locally-scoped, correctly-scaled Earth mesh (plain `<mesh><sphereGeometry args={[6371, 64, 64]}/>...`) and its own camera framing, inline in the new debug route — not a shared component. Migrating the real scene to real-km scale is M1.9's integration job.
- **Scale convention for the new code: 1 scene unit = 1 km.** This is executing the architecture CLAUDE.md already calls "decisions that must not be retrofitted" (Earth radius 6371 km), not a new architecture decision — no ask-first needed. It is also what makes the zero-copy position upload in Task 3 possible: `FrameState.positions` is already km, J2000 — with a 1:1 scale there is no per-frame unit conversion over 46,250×3 floats, only a direct buffer share. Camera-relative origin and a logarithmic depth buffer (needed for Phase 7/8's ~10²⁰:1 range per Cosmic-Scales-Brief) are **not** needed at this scale: GEO is ~42,164 km from Earth's centre, comfortably inside float32 precision.
- **`aRadius` cannot be sourced from real per-object physical-size data — verified, not assumed.** `packages/orcas-physics/src/types.ts`'s `OmmRecord` (the literal CelesTrak OMM schema this codebase ingests) has **no RCS_SIZE field at all** — it was never ingested. The brief's attribute table says "physical size, from RCS where known"; there is currently no "where known" case. Rather than inventing a per-object size (an honesty-rules violation — Rules.md §7, "never invent numbers"), Task 1 uses one uniform placeholder radius for every object, named and commented as exactly that. Ingesting real `RCS_SIZE` is a `Data-Strategy.md` gap, not this milestone's job.
- **`aEntityId` is the object's index into the `objects`/`FrameState` arrays (0..N−1), not its NORAD number.** Positions/velocities/flags are already keyed by that same index (see `frame-state.ts`'s `evaluateFrame` loop) — reusing it keeps one indexing scheme everywhere. It also sidesteps the brief's own float32-precision caveat on this attribute ("or `uvec2` for >2²⁴") since indices stay far below 2²⁴ long before NORAD catalog numbers would. M1.5 (GPU picking) resolves a picked index back to identity via `objects[index].norad` — nothing in M1.3 reads this attribute yet; it exists because the brief's Tier 0 attribute table specifies it, and building it now costs nothing extra since Task 1 already walks every object.
- **`aFlags` is a single visibility boolean in M1.3, not a full bitfield.** The brief specifies it as a bitfield because M1.4 needs multiple filter bits and M1.6's focus/dim needs a membership bit; neither exists yet. M1.3 packs a constant `1.0` (visible) for every object and the shader checks `aFlags < 0.5` to discard — encoding additional bits later (M1.4) extends this without renaming the attribute.
- **The brief's per-object `isFocusMember` dim multiply is a uniform-only no-op in M1.3, not a per-object attribute.** No selection system exists yet (that's M1.5/M1.6); the shader still declares `uFocusActive` (fixed at `0.0`) and `uDimFactor` (fixed at `0.3`, the already-decided D6 value — Design.md §3) so M1.5 only has to flip the uniform and add the one missing per-object attribute, not restructure the shader.
- **Binary occlusion by Earth is already correct for free via the standard WebGL depth test** (points behind the opaque Earth mesh fail the depth test like any other geometry) — no shader-side occlusion code is needed in M1.3. The brief's M1.4 "occlusion fade at the limb" is a different, smoother effect (dimming near the visual horizon, not binary hide/show) and stays out of scope here.
- **Stale objects (`FrameState.flags` `Flag.Stale`) are rendered at full brightness in M1.3, not dimmed.** `frame-state.ts` guarantees a stale object holds its last valid (non-`NaN`) position, so rendering it is safe; the brief's "stale objects render at 40%" behaviour is explicitly M1.4's job, not M1.3's.
- Colour is sourced from `tokens.css`'s `--orca-cyan` via `getComputedStyle`, never a hardcoded hex literal in the shader-setup code (Rules.md's ban on colour literals outside `tokens.css`) — a GLSL uniform can't reference a CSS variable directly, so Task 4 reads the token once at mount and converts it to a `THREE.Color`.
- Numeric shader tuning constants with no value specified anywhere in the brief (`uMinPointPx`, `uFloorBrightness`, the fragment falloff shape) are **not** invented with false precision — each is written as a plainly-labelled starting value ("chosen empirically for this task"), verified and, if changed, updated in place during Task 7's live check. `uDimFactor = 0.3` is the one exception — that value is an already-decided design constant (D6), not invented here.

```typescript
// frontend/src/renderer/points/points-attributes.ts
import type { ObjectMeta } from '../../data/catalog-types.js';

/**
 * No per-object physical size exists in the ingested data: `OmmRecord`
 * (packages/orcas-physics/src/types.ts) carries no RCS_SIZE field at all —
 * verified by reading the CelesTrak OMM schema this codebase actually
 * ingests, not assumed. Rather than invent a per-object size (Rules.md
 * §7, "never invent numbers"), every point uses this one placeholder —
 * 10 metres, a plausible order of magnitude for a small satellite, not a
 * measurement. Real RCS ingestion is a Data-Strategy follow-up.
 */
export const PLACEHOLDER_RADIUS_KM = 0.01;

/** aFlags sentinel: bit 0 set means "visible." M1.4 adds more bits later
 * without renaming this attribute. */
export const FLAG_VISIBLE = 1.0;

/**
 * `aEntityId`: each point's own index into the `objects`/`FrameState`
 * arrays (0..count-1) — the same index every other per-object buffer
 * already uses (see frame-state.ts's `evaluateFrame`). Using the array
 * index rather than the NORAD number also sidesteps the brief's own
 * float32-precision caveat on this attribute, since indices stay far
 * below 2^24 long before catalog numbers would.
 */
export function packEntityIds(count: number): Float32Array {
  const ids = new Float32Array(count);
  for (let i = 0; i < count; i++) ids[i] = i;
  return ids;
}

/** `aRegime`: the object's already-classified Regime enum value, copied
 * verbatim — LEO=0, MEO=1, GEO=2, HEO=3, Unknown=4. */
export function packRegimes(objects: readonly ObjectMeta[]): Float32Array {
  const regimes = new Float32Array(objects.length);
  for (let i = 0; i < objects.length; i++) regimes[i] = objects[i].regime;
  return regimes;
}

/** `aRadius`, km. See `PLACEHOLDER_RADIUS_KM`'s docstring for why every
 * entry is currently the same value. */
export function packRadii(count: number): Float32Array {
  return new Float32Array(count).fill(PLACEHOLDER_RADIUS_KM);
}

/** `aFlags`. Every object is visible in M1.3 — per-object filtering is
 * M1.4's job. */
export function packVisibilityFlags(count: number): Float32Array {
  return new Float32Array(count).fill(FLAG_VISIBLE);
}
```

```typescript
// frontend/src/renderer/points/points-shading.ts

/**
 * The Tier 0 apparent-size/brightness law (brief §B.3). Mirrors exactly
 * what the vertex shader in TierZeroPoints.tsx computes in GLSL — this
 * function exists so the formula is unit-testable without a GPU
 * (M1.3-Explained.md §6.2's convention) and so the /points debug route
 * can show an "expected" value per cross-checked object.
 *
 * All distances/radii in km. `pixelsPerRadian` is screen pixels per
 * radian of vertical field of view at the current viewport height.
 */
export function computePointShading(
  radiusKm: number,
  distanceKm: number,
  pixelsPerRadian: number,
  minPointPx: number,
  baseBrightness: number,
  floorBrightness: number,
): { drawPx: number; brightness: number } {
  const truePx = (radiusKm * pixelsPerRadian) / distanceKm;
  const drawPx = Math.max(truePx, minPointPx);
  const areaRatio = Math.min(1, (truePx * truePx) / (drawPx * drawPx));
  const brightness = Math.max(baseBrightness * areaRatio, floorBrightness);
  return { drawPx, brightness };
}
```

```typescript
// frontend/src/renderer/points/points-geometry.ts
import { BufferAttribute, BufferGeometry } from 'three';
import type { ObjectMeta } from '../../data/catalog-types.js';
import { packEntityIds, packRegimes, packRadii, packVisibilityFlags } from './points-attributes.js';

/**
 * Builds the Tier 0 `THREE.BufferGeometry` (brief §B.3): one `position`
 * attribute per frame-updated object, plus four static attributes built
 * once from the catalogue. `positions` is wrapped **by reference** — the
 * caller (TierZeroPoints.tsx) mutates the same array in place every
 * frame via M1.2's FrameState and flips `needsUpdate`, so this function
 * must never copy it (that copy would be exactly the per-frame
 * allocation the milestone's DoD forbids).
 */
export function createPointsGeometry(
  objects: readonly ObjectMeta[],
  positions: Float32Array,
): BufferGeometry {
  const geometry = new BufferGeometry();
  geometry.setAttribute('position', new BufferAttribute(positions, 3));
  geometry.setAttribute('aEntityId', new BufferAttribute(packEntityIds(objects.length), 1));
  geometry.setAttribute('aRegime', new BufferAttribute(packRegimes(objects), 1));
  geometry.setAttribute('aRadius', new BufferAttribute(packRadii(objects.length), 1));
  geometry.setAttribute('aFlags', new BufferAttribute(packVisibilityFlags(objects.length), 1));
  return geometry;
}
```

```typescript
const VERTEX_SHADER = /* glsl */ `
attribute float aEntityId;
attribute float aRegime;
attribute float aRadius;
attribute float aFlags;

uniform float uPixelsPerRadian;
uniform float uMinPointPx;
uniform float uDpr;
uniform float uBaseBrightness;
uniform float uFloorBrightness;
uniform float uDimFactor;
uniform float uFocusActive;

void main() {
  if (aFlags < 0.5) {
    // Filtered-out objects are moved off clip space in the shader, not
    // culled on the CPU (brief §B.3) — no object exists in M1.3, this
    // branch exists for M1.4 to actually use.
    gl_Position = vec4(2.0, 2.0, 2.0, 1.0);
    vBrightness = 0.0;
    return;
  }

  vec4 mvPosition = modelViewMatrix * vec4(position, 1.0);
  float dist = max(length(mvPosition.xyz), 1e-6);

  // 1. apparent size, with a floor that does NOT flatten brightness.
  float truePx = aRadius * uPixelsPerRadian / dist;
  float drawPx = max(truePx, uMinPointPx);
  gl_PointSize = drawPx * uDpr;

  // 2. compensate: an object drawn larger than reality is dimmed by the
  //    area ratio, so distant debris stays visible but recedes.
  float brightness = uBaseBrightness * min(1.0, (truePx * truePx) / (drawPx * drawPx));
  brightness = max(brightness, uFloorBrightness);

  // 3. D6 focus dim — uFocusActive is fixed at 0.0 in M1.3 (no selection
  //    system exists yet, that's M1.5/M1.6); this line is a no-op today.
  brightness *= mix(1.0, uDimFactor, uFocusActive);

  vBrightness = brightness;
  gl_Position = projectionMatrix * mvPosition;
}
`;

const FRAGMENT_SHADER = /* glsl */ `
precision mediump float;

varying float vBrightness;
uniform vec3 uColor;

void main() {
  // Soft radial falloff on gl_PointCoord: a Gaussian-ish core plus a
  // faint halo (brief §B.3). The 4.0 / 0.12 constants below are chosen
  // empirically for this task and tuned live in Task 7 — not spec values.
  vec2 fromCenter = gl_PointCoord - vec2(0.5);
  float d = length(fromCenter) * 2.0; // 0 at center, 1 at edge
  float core = exp(-d * d * 4.0);
  float halo = smoothstep(1.0, 0.0, d) * 0.12;
  float alpha = clamp(core + halo, 0.0, 1.0) * vBrightness;
  if (alpha < 0.003) discard;
  gl_FragColor = vec4(uColor, alpha);
}
`;

interface TierZeroPointsProps {
  readonly objects: readonly ObjectMeta[];
  readonly frameStateRef: MutableRefObject<FrameState>;
}

/** Reads --orca-cyan from tokens.css rather than hardcoding the hex —
 * Rules.md bans colour literals outside tokens.css; a GLSL uniform can't
 * reference a CSS variable directly, so this is the one-time bridge. */
function readCyanToken(): Color {
  const hex = getComputedStyle(document.documentElement).getPropertyValue('--orca-cyan').trim();
  return new Color(hex || '#00E5FF');
}

/**
 * Tier 0 GPU point renderer (brief §B.3): one `THREE.Points`, one draw
 * call, every object in the catalogue. Positions come from M1.2's
 * `FrameState` — the SAME buffer every frame, flagged `needsUpdate`
 * rather than replaced, so this component allocates nothing per frame.
 */
export function TierZeroPoints({ objects, frameStateRef }: TierZeroPointsProps) {
  const pointsRef = useRef<Points>(null);
  const { size, camera } = useThree();

  const geometry = useMemo(
    () => createPointsGeometry(objects, frameStateRef.current.positions),
    // eslint-disable-next-line react-hooks/exhaustive-deps -- objects/frameStateRef are stable for the route's lifetime, same precedent as use-simulation-loop.ts
    [],
  );

  const material = useMemo(
    () =>
      new ShaderMaterial({
        vertexShader: VERTEX_SHADER,
        fragmentShader: FRAGMENT_SHADER,
        transparent: true,
        depthWrite: false,
        blending: AdditiveBlending,
        uniforms: {
          uPixelsPerRadian: { value: 0 },
          uMinPointPx: { value: 1.5 }, // chosen empirically, tune in Task 7
          uDpr: { value: Math.min(window.devicePixelRatio, 2) }, // Rules.md perf ceiling: dpr capped at 2
          uBaseBrightness: { value: 1.0 },
          uFloorBrightness: { value: 0.05 }, // chosen empirically, tune in Task 7
          uDimFactor: { value: 0.3 }, // D6, Design.md §3 — not invented here
          uFocusActive: { value: 0.0 }, // no selection system until M1.5
          uColor: { value: readCyanToken() },
        },
      }),
    [],
  );

  useEffect(() => () => {
    geometry.dispose();
    material.dispose();
  }, [geometry, material]);

  useFrame(() => {
    // Zero-allocation per-frame work: flag the SAME position buffer for
    // re-upload (M1.2 already wrote this frame's values into it), and
    // update the two camera-dependent uniforms with cheap arithmetic.
    geometry.getAttribute('position').needsUpdate = true;

    const perspectiveCamera = camera as unknown as { fov: number };
    const verticalFovRad = (perspectiveCamera.fov * Math.PI) / 180;
    material.uniforms.uPixelsPerRadian.value = size.height / verticalFovRad;
  });

  // frustumCulled disabled: three.js would need to recompute the geometry's
  // bounding sphere from `position` every time it changes to cull correctly,
  // which is exactly the per-frame CPU cost this component exists to avoid.
  return <points ref={pointsRef} geometry={geometry} material={material} frustumCulled={false} />;
}
```

```typescript
// Add to the imports at the top of PointsDebug.tsx:
import { useEffect, useState } from 'react';
import { satrecFromOmm, propagate, temeToJ2000Matrix, applyMat3 } from '@orcas/physics';
import { TelemetryReadout } from '../../ui/TelemetryReadout.js';
import { computePointShading } from './points-shading.js';
import { PLACEHOLDER_RADIUS_KM } from './points-attributes.js';

const CROSS_CHECK_COUNT = 10;
const POLL_MS = 100; // matches SimulationDebug.tsx's existing ≤10Hz UI-mirror pattern

interface CrossCheckRow {
  readonly norad: string;
  readonly renderedKm: { x: number; y: number; z: number };
  readonly directKm: { x: number; y: number; z: number };
  readonly deltaM: number;
  readonly drawPx: number;
}

function buildCrossCheckRows(
  objects: readonly ObjectMeta[],
  frameState: { positions: Float32Array; epochMs: number },
  pixelsPerRadian: number,
): CrossCheckRow[] {
  const rows: CrossCheckRow[] = [];
  const atMs = frameState.epochMs;
  const at = new Date(atMs);

  for (let i = 0; i < Math.min(CROSS_CHECK_COUNT, objects.length); i++) {
    const object = objects[i];
    const satrec = satrecFromOmm(object.record);
    const rawDirect = propagate(satrec, at, object.norad);
    const directKm = applyMat3(temeToJ2000Matrix(at), rawDirect.positionEciKm);

    const renderedKm = {
      x: frameState.positions[i * 3],
      y: frameState.positions[i * 3 + 1],
      z: frameState.positions[i * 3 + 2],
    };

    const deltaM =
      Math.hypot(
        directKm.x - renderedKm.x,
        directKm.y - renderedKm.y,
        directKm.z - renderedKm.z,
      ) * 1000;

    const distanceKm = Math.hypot(directKm.x, directKm.y, directKm.z);
    const { drawPx } = computePointShading(PLACEHOLDER_RADIUS_KM, distanceKm, pixelsPerRadian, 1.5, 1, 0.05);

    rows.push({ norad: object.norad, renderedKm, directKm, deltaM, drawPx });
  }

  return rows;
}
```
